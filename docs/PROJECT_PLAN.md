# План разработки akapp-stemmann.su

Статус: рабочая версия; основные ограничения подтверждены, открытые вопросы перечислены в разделе 6.

## 1. Зафиксированные ограничения

- Next.js App Router, TypeScript, Tailwind CSS.
- Полностью статическая сборка: `output: "export"`.
- Размещение готовой папки `out` на обычном хостинге Beget.
- Основные и изменяемые данные хранятся в JSON-файлах внутри Git-репозитория.
- CMS и серверная база данных не используются.
- Дизайн-макет предоставляет заказчик.
- Основной поисковик для оптимизации — Яндекс.
- Действующий домен: `akapp-stemmann.su`.
- Область сайта ограничена продукцией AKAPP-STEMMANN.
- Программа поставок, сторонние бренды и остальные направления старого сайта не переносятся.
- Каталог включает три направления: шинопроводы, фестонные системы и кабельные барабаны.
- Создаются страницы серий с таблицами модификаций; отдельные страницы каждой модификации не нужны.
- Фильтрация каталога не требуется.
- Язык сайта — русский, регион продвижения — вся Россия.
- Исходники находятся в приватном GitHub-репозитории `https://github.com/NikDemik/akapp-stemmann.git`.
- Формы: обычная заявка, запрос цены и подбор аналогов.
- Заявки отправляются на email; антиспам — Yandex SmartCaptcha.
- Новый сайт заменяет старый целиком за один запуск.
- Существующие пути URL сохранять не требуется; для нового сайта проектируется чистая структура адресов.
- Доступны 10 PDF-каталогов в `docs/catalogs`, общий объем — 159 страниц.
- Юридические и корпоративные сведения находятся в `docs/legal/Requisites.rtf`.
- Предоставляется готовая HTML-верстка главной; внутренние шаблоны разрабатываются на ее основе.
- Поиск по сайту не требуется.
- Формы используют минимальный согласованный набор полей без загрузки вложений.
- Заявки отправляются на `zapros@trolleynyi-shinoprovod.ru`, без копии.
- Опросный лист отправляется клиенту по email по запросу и не загружается через форму.
- Технические данные, извлеченные из PDF, проверяет разработчик.
- Репозиторий приватный и создается заказчиком в GitHub.
- Предпросмотр выполняется локально; отдельный тестовый поддомен не используется.
- Целевой срок первого production-релиза — один рабочий день после получения HTML-шаблона и необходимых доступов.

## 2. Целевой процесс публикации

1. Контент или код изменяется в Git-репозитории.
2. JSON проверяется схемами и автоматическими тестами.
3. Выполняются lint, проверка типов, тесты и production-сборка.
4. Next.js генерирует статические HTML/CSS/JS-файлы в `out`.
5. Сборка загружается на Beget по SFTP.
6. После публикации выполняется smoke-проверка основных URL, форм, robots.txt и sitemap.xml.

Предпочтительный способ запуска — GitHub Actions: проверка, сборка и загрузка артефакта на Beget по SFTP. Ручной деплой сохраняется как резервный сценарий.

Состав информационных страниц и окончательные наименования URL утверждаются до разработки шаблонов.

## 3. Этапы работ

### Этап 0. Предпроектное обследование

- Получить дизайн-макеты, UI-kit, логотипы, шрифты и требования к адаптивности.
- Выгрузить полный список URL действующего сайта.
- Получить данные Яндекс Вебмастера и Метрики: страницы входа, запросы, показы, клики, внешние ссылки и 404.
- Провести инвентаризацию HTML-страниц, изображений, документов и PDF-каталогов.
- Разделить контент на категории: сохранить, переработать, объединить, удалить.
- Составить карту `старый URL → новый URL / 410` только для тематических страниц AKAPP-STEMMANN и удаляемых разделов.
- Зафиксировать структуру каталога и обязательные поля данных.
- Определить источники и правила переноса данных из каталогов.

Результат: утвержденная карта сайта, URL-карта, контентная модель и список шаблонов страниц.

### Этап 1. Создание проекта

- Создать Next.js-проект с App Router, TypeScript, Tailwind CSS и ESLint.
- Настроить `output: "export"`.
- Зафиксировать новые человекочитаемые URL и включить `trailingSlash`, удобный для статического Apache-хостинга.
- Отключить серверную оптимизацию `next/image` либо подключить статический image loader.
- Добавить форматирование, проверку типов и единые команды npm.
- Создать структуру каталогов приложения, компонентов, данных, схем и утилит.
- Добавить `.env.example` только для несекретных имен переменных; секреты не хранить в Git.
- Подключить журнал разработки.

Минимальные проверки этапа: lint, typecheck и пустая production-сборка.

### Этап 2. Проектирование JSON-данных

- Разделить данные на небольшие файлы: категории, производители, серии, товары, документы и настройки.
- Не использовать один общий файл со всем каталогом.
- Описать TypeScript-типы и схемы валидации, например через Zod.
- Ввести стабильные `id`, `slug`, связи и порядок сортировки.
- Добавить SEO-поля: `title`, `description`, `h1`, `canonical`, `index`.
- Описать характеристики как структурированные пары или группы, а не как HTML-строки.
- Предусмотреть изображения, PDF, чертежи, связанные товары и источники данных.
- Написать проверку уникальности `id`, `slug`, URL и обязательных SEO-полей.

Результат: валидируемый формат данных, пригодный для автоматической генерации страниц.

### Этап 3. Перенос и нормализация контента

- Извлечь тексты и медиа из существующего сайта.
- Извлечь характеристики из предоставленных каталогов.
- Нормализовать единицы измерения, названия производителей и обозначения моделей.
- Удалить дубли и технический мусор Website X5.
- Сохранить источник и дату проверки импортируемых данных.
- Перенести важные сведения из PDF в видимый HTML; PDF оставить как загружаемый документ.
- Проверить права на использование текстов, изображений и каталогов.
- Отметить контент, требующий ручной технической проверки.

Результат: заполненные и прошедшие валидацию JSON-файлы.

### Этап 4. Дизайн-система и базовая верстка

- Разобрать макеты на токены: цвета, типографика, сетка, отступы, радиусы и состояния.
- Подключить локальные шрифты и исключить лишние внешние зависимости.
- Реализовать базовые компоненты: контейнер, кнопки, ссылки, карточки, таблицы и формы.
- Реализовать шапку, многоуровневое меню, поиск, хлебные крошки и подвал.
- Проверить desktop, tablet и mobile.
- Обеспечить клавиатурную навигацию, видимый focus и корректную семантику HTML.

Результат: согласованный набор переиспользуемых компонентов.

### Этап 5. Шаблоны и статическая генерация страниц

- Главная страница.
- Страницы направлений и категорий.
- Страницы производителей и серий.
- Страница серии с таблицей модификаций.
- Раздел каталогов и документов.
- Информационные страницы: о компании, доставка, контакты, политика и согласия.
- Страница 404.
- Генерация всех динамических маршрутов через `generateStaticParams()`.
- Проверка, что значимый контент присутствует в исходном HTML без выполнения JavaScript.

Результат: полный статический набор страниц в `out`.

### Этап 6. SEO под Яндекс

- Сформировать уникальные `title`, `description` и H1 для индексируемых страниц.
- Добавить canonical на каждую индексируемую страницу.
- Реализовать корректную иерархию H1–H3 и перелинковку.
- Генерировать `robots.txt` и XML Sitemap только с каноническими индексируемыми URL.
- Добавить Schema.org/JSON-LD: Organization, BreadcrumbList и Product там, где данные соответствуют разметке.
- Добавить Open Graph и favicon.
- Настроить правильные 404, 301 и отсутствие циклов редиректов.
- Закрыть от индексации служебные результаты поиска и бесполезные параметрические URL.
- Добавить верификацию Яндекс Вебмастера.
- Проверить страницы инструментами Яндекс Вебмастера: ответ сервера, robots.txt, Sitemap и валидатор микроразметки.

Результат: технически индексируемый сайт с управляемыми сниппетами и сохраненной историей URL.

### Этап 7. Формы и интеграции

- Определить обработчик заявок: PHP на Beget либо внешний сервис.
- Реализовать серверную валидацию, антиспам и ограничение частоты запросов на стороне обработчика.
- Добавить согласие на обработку персональных данных.
- Не помещать секреты почты, API или CAPTCHA в клиентский JavaScript.
- Настроить цели Яндекс Метрики: отправка формы, клик по телефону, email и скачивание каталога.
- Протестировать доставку заявок и журналирование ошибок без записи персональных данных в публичные логи.

Результат: проверенный канал получения заявок и измеряемые конверсии.

### Этап 8. Качество и производительность

- Проверить TypeScript, ESLint и production-сборку.
- Валидировать все JSON-файлы.
- Проверить внутренние ссылки, отсутствующие изображения и PDF.
- Проверить metadata, canonical, sitemap и robots.
- Проверить адаптивность в актуальных браузерах.
- Проверить доступность основных сценариев с клавиатуры.
- Оптимизировать изображения и размеры JS/CSS.
- Выполнить Lighthouse-проверку ключевых шаблонов.
- Провести ручной smoke-тест всех типов страниц и формы заявки.

Результат: отчет о проверках и устраненные критические дефекты.

### Этап 9. Подготовка миграции

- Развернуть закрытый от индексации предпросмотр.
- Согласовать контент и дизайн.
- Зафиксировать финальную карту новых URL и правила обработки старых адресов.
- Сформировать `.htaccess`: тематические старые страницы направить на наиболее близкие новые, а для удаляемых нерелевантных разделов вернуть 410 или 404.
- Не перенаправлять все удаленные страницы на главную.
- Проверить цепочки редиректов и canonical.
- Сделать резервную копию текущего сайта и конфигурации хостинга.
- Подготовить план отката и чек-лист переключения.

Результат: проверенная release-сборка и безопасный сценарий запуска.

### Этап 10. Деплой на Beget

- Собрать сайт в чистом окружении.
- Сохранить идентификатор коммита и контрольную информацию о сборке.
- Загрузить содержимое `out` и необходимые серверные файлы на Beget.
- Установить `.htaccess`, PHP-обработчик форм и конфигурацию, если они используются.
- Проверить HTTPS, основное зеркало, редиректы и пользовательскую 404.
- Проверить главную, категории, товары, изображения, PDF и формы.
- Проверить доступность `/robots.txt` и `/sitemap.xml` с кодом 200.
- Записать результат в журнал деплоев.

Результат: опубликованный сайт и подтвержденный smoke-тест production.

### Этап 11. Действия после запуска

- Добавить Sitemap в Яндекс Вебмастер.
- Отправить важные страницы на переобход.
- Проверить региональность, HTTPS и главное зеркало.
- Сопоставить данные Метрики до и после запуска.
- Ежедневно проверять 404, ошибки обхода и формы в первую неделю.
- Еженедельно проверять индексирование и позиции в первый месяц.
- Не удалять старые редиректы после стабилизации индекса.
- Зафиксировать результаты и найденные проблемы в журнале разработки.


## 5. Критерии готовности

- Все утвержденные страницы существуют и доступны без JavaScript.
- Каждый старый значимый URL сохранен или имеет точечный постоянный редирект.
- JSON проходит автоматическую валидацию.
- Нет битых внутренних ссылок, изображений и документов.
- Для индексируемых страниц заданы уникальные metadata, H1 и canonical.
- Robots.txt и Sitemap доступны и проходят проверку Яндекса.
- Формы доставляют тестовые заявки и защищены от базового спама.
- Production-сборка воспроизводима из Git.
- Выполнена и проверена резервная копия старого сайта.
- В журнале записаны версия, дата, проверки, деплой и способ отката.

## 6. Открытые вопросы перед началом разработки

- HTML-верстка главной страницы получена: `/external/index.html`.
- Точный состав полей трех форм и обязательность телефона/email.
- Идентификатор Яндекс Метрики и код подтверждения Яндекс Вебмастера.
- Публичный ключ и серверный секрет Yandex SmartCaptcha.
- Адрес репозитория получен: `https://github.com/NikDemik/akapp-stemmann.git`.
- SFTP-реквизиты Beget, корневая папка домена и доступный вариант запуска PHP.
- Подтверждение телефонов, адреса, режима работы и окончательных реквизитов из `docs/legal/Requisites.rtf`.
- Решение: выполнять первый деплой вручную или сразу настраивать GitHub Actions.

## 7. Однодневный план реализации

Однодневный выпуск рассматривается как интенсивный production MVP без циклов изменения дизайна. Критические входные данные — HTML-шаблон, доступы Beget, SmartCaptcha и Метрика — должны быть доступны до начала.

| Время | Работы | Контрольный результат |
|---|---|---|
| 00:00–00:45 | Проверка HTML, PDF, реквизитов и текущих страниц | Финальная карта страниц и серий |
| 00:45–01:30 | Создание Next.js-проекта и статической конфигурации | Чистая сборка `out` |
| 01:30–03:00 | JSON-схемы, валидация и первичное извлечение каталогов | Валидные категории и серии |
| 03:00–05:00 | Перенос дизайна, layout и общие компоненты | Главная и базовые шаблоны |
| 05:00–07:00 | Страницы трех направлений, серий и документы | Полный набор статических маршрутов |
| 07:00–08:00 | Metadata, canonical, Schema.org, robots и Sitemap | SEO-проверка сборки |
| 08:00–09:00 | Три формы, PHP-обработчик, email и SmartCaptcha | Доставка тестовой заявки |
| 09:00–10:00 | Адаптивность, ссылки, PDF, 404 и производительность | Пройден локальный smoke-тест |
| 10:00–11:00 | Резервная копия и деплой на Beget | Production доступен |
| 11:00–12:00 | Production smoke-тест, Метрика и Вебмастер | Релиз зафиксирован в журнале |

### Ограничение срока

В каталогах 159 страниц, а часть русскоязычных PDF имеет некорректный текстовый слой. За один день реалистично извлечь и вручную проверить основные характеристики на уровне серий. Полная построчная сверка всех таблиц и артикулов должна выполняться по приоритету; непроверенные значения не публикуются как подтвержденные.
