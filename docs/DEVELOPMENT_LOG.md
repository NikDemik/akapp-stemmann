# Журнал разработки

Этот документ используется как журнал проекта и как шаблон для аналогичных задач.

## Правила ведения

1. Запись создается для каждого законченного изменения, решения, импорта данных и деплоя.
2. Записи добавляются в начало раздела «Хронология»; завершенные записи не переписываются задним числом, кроме исправления явной ошибки.
3. Указываются фактические проверки и их результат, а не только намерение проверить.
4. Для каждого деплоя фиксируются Git commit/tag, состав сборки, результат smoke-теста и способ отката.
5. Секреты, пароли, токены, персональные данные и содержимое заявок в журнал не записываются.
6. Незавершенные действия переносятся в «Следующие действия» и не отмечаются как выполненные.
7. Любое изменение URL, индексирования, canonical, metadata, robots.txt, sitemap.xml или микроразметки отдельно отмечается в поле «SEO-влияние».
8. Если проверка не выполнялась, записывается `не выполнялась` с причиной.

## Хронология

### 2026-09-16 — FEAT-001 — Первая статическая версия сайта

- Запрос: начать разработку по HTML-шаблону `/external/index.html` и подготовить проект для Beget.
- Входные материалы: HTML и изображение дизайна, 10 PDF-каталогов, файл реквизитов, GitHub-репозиторий.
- Выполнено:
  - создан Next.js 16 проект с TypeScript, Tailwind CSS и статическим экспортом;
  - реализованы главная, 3 категории, 15 страниц серий, каталог документов, информационные и юридические страницы, 404;
  - данные вынесены в JSON и проверяются Zod при сборке и отдельным скриптом;
  - PDF и изображения каталогов включены в статическую сборку;
  - добавлены canonical, metadata, Open Graph, Organization/Product/BreadcrumbList, robots.txt и sitemap.xml;
  - добавлен PHP-обработчик заявок с ограничением частоты, поддержка Yandex SmartCaptcha, цели Метрики и Apache-конфигурация Beget;
  - создана инструкция обновления JSON и ручного деплоя.
- Измененные URL: создана новая структура `/shinoprovody/`, `/festonnye-sistemy/`, `/kabelnye-barabany/`, страницы серий и информационные разделы.
- SEO-влияние: все коммерческие страницы статические и индексируемые; юридические страницы исключены из индексирования; Sitemap содержит канонические URL.
- Проверки и фактический результат: `validate:data` — 3 категории и 15 серий корректны; `typecheck` — успешно; `next build` — успешно, создано 30 статических страниц; `.htaccess` добавлен в `out`.
- Не выполненные проверки и причина: отправка email, CAPTCHA, Метрика и Вебмастер требуют production-ключей и публикации на Beget; технические характеристики требуют финальной ручной сверки разработчиком.
- Риски/ограничения: тексты юридических страниц являются рабочей редакцией и требуют проверки реквизитов оператора; PHP `mail()` необходимо проверить на production.
- Способ отката: до публикации отсутствует; при production-деплое восстановить резервную копию прежнего `public_html`.
- Следующие действия: визуальная QA, финальная техническая сверка, добавление ключей SmartCaptcha/Метрики, резервная копия старого сайта и загрузка `out`.

### 2026-09-15 — PLAN-003 — Утверждение однодневного сценария

- Запрос: подготовить проект к максимально быстрому запуску за один день.
- Входные материалы:
  - 10 PDF-каталогов, 159 страниц, в `docs/catalogs`;
  - реквизиты в `docs/legal/Requisites.rtf`;
  - HTML-шаблон главной ожидается.
- Принятые решения:
  - все три направления реализуются одновременно;
  - внутренние страницы проектируются на основе HTML главной;
  - поиск и фильтрация не реализуются;
  - формы используют минимальные поля и не принимают файлы;
  - заявки отправляются на `zapros@trolleynyi-shinoprovod.ru`;
  - приватный GitHub-репозиторий создает заказчик;
  - приемка выполняется локально без тестового поддомена;
  - первый релиз выполняется на основном домене после резервного копирования.
- Проверки:
  - все PDF открываются, не зашифрованы и содержат 159 страниц суммарно;
  - у нескольких русскоязычных PDF текст извлекается с поврежденной кодировкой;
  - файл реквизитов присутствует и имеет формат RTF.
- SEO-влияние: выпуск всех направлений происходит одновременно; статический HTML, metadata, Sitemap и микроразметка входят в критический путь первого релиза.
- Риски: полная ручная проверка каждой таблицы 159-страничного набора не укладывается в срок без приоритизации; сомнительные значения нельзя публиковать без визуальной сверки.
- Следующие действия: получить HTML-шаблон, ключи интеграций, адрес GitHub и доступ Beget.

## Журнал решений

Используется для решений, влияющих на архитектуру, URL, данные или сопровождение.

### ADR-001 — Статический файловый каталог без CMS

- Дата: 2026-09-15.
- Статус: принято.
- Контекст: сайт размещается на обычном хостинге Beget; данные изменяются разработчиком или сотрудником компании.
- Решение: Next.js static export, JSON в GitHub, без CMS и базы данных.
- Причины: небольшой контролируемый каталог, отсутствие динамической фильтрации и серверного приложения.
- Последствия и ограничения: любое изменение данных требует проверки, новой сборки и публикации; необходима инструкция редактора JSON.

### ADR-002 — Новая структура URL

- Дата: 2026-09-15.
- Статус: принято.
- Контекст: у текущего сайта нет значимого трафика, старые адреса сохранять не требуется.
- Решение: создать короткие тематические URL для трех направлений и серий.
- Последствия и ограничения: релевантные старые страницы желательно перенаправить на соответствующие новые; нерелевантные удаленные разделы должны возвращать 410 или 404, а не вести на главную.

### ADR-003 — Единовременная замена production

- Дата: 2026-09-15.
- Статус: принято.
- Контекст: новый сайт должен полностью заменить Website X5 на основном домене.
- Решение: выполнить один production-релиз после полной приемки и резервного копирования.
- Последствия и ограничения: обязательны предпросмотр, полный smoke-тест, карта старых URL и проверенный сценарий отката.

### ADR-004 — Однодневный production MVP

- Дата: 2026-09-15.
- Статус: принято.
- Контекст: приоритет — максимальная скорость, все три продуктовых направления должны выйти одновременно.
- Решение: выполнить интенсивный цикл до 12 часов без промежуточного тестового домена; локальная приемка предшествует единовременному переключению production.
- Причины: нулевая текущая посещаемость и ограниченный набор шаблонов страниц.
- Последствия и ограничения: дизайн внутренних страниц выводится из главной; публикуются только проверенные технические данные; расширенная контентная сверка при необходимости продолжается после первого релиза отдельными исправлениями.
